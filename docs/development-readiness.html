已接入的编辑闭环

打开素材 → 调色与调正 → 视频选择片段 / 封面 / 声音 → 另存副本或生成 Live。原生工作台现在可执行这条流程，最低 macOS 15，当前无需第三方库或模型 API。

LUT 调色导入 2–128 阶 .cube；暖调 / 柔和预设；强度、原片对比；图片、视频和重制 Live 共用处理规则。默认在非线性 sRGB 空间应用 LUT，导入表可明确选择 Rec.709；输入域归一化后插值；零 / 半 / 全强度和非默认域像素测试通过。相机 Log 转换不自动猜测，DJI 专用转换表需先确定输入空间。
HDR 图片读取 HDR 增益图；一次生成最长边 1600px 浮点预览，Metal RGBA16Float / EDR 画布；按当前屏幕亮度空间适配。合成带增益图 HEIC 重新打开后，浮点预览保留大于 1 的亮度。当前屏幕没有额外 HDR 亮度空间，界面正确显示“ HDR → SDR 预览”；外接 HDR 屏视觉效果未验收。
HDR 视频未调色 / 未旋转时用 AVPlayer 保留源 HDR 播放；创意 LUT、几何编辑与当前成品走 SDR 管线。合成 10-bit HEVC PQ / HLG 两个案例通过：原生预览资源保留 HDR，SDR 输出标为 Rec.709。真实手机 Dolby Vision、4K 与显示性能仍待验证。
片段与声音播放 / 定位、起止点、3 秒快速选择、当前位置设封面；原声音量 / 静音；单段 BGM 和独立音量。预览与导出使用同一片段 / LUT / 几何 / 混音配置。BGM 从片段开头播放，不足不循环；目前没有音乐偏移、淡入淡出、多轨编辑或单独试听音量。
Live 制作0.5–3 秒片段生成 JPEG + MOV，封面从最终视频提取；写入共同 content identifier 和 still-image-time，保存前让 Photos 检查配对。自动化测试与窗口导出均经系统识别，可在 PHLivePhotoView 播放；重新打开已有 Live 会读取并保留原封面时间。默认输出 SDR；另有实验性 SDR 派生 HDR Live（增益图 HEIC + HEVC Main10 HLG），真实 4K 资源经 Photos 配对检查。Mac 照片库导入 / iPhone 实机导入未验收。已有 Live 重制使用动态视频帧，可能低于原静态资源分辨率。
保存与交互PNG / MOV 另存，Live 新建文件夹；原件保留；Live 内含 recipe.json 和实际所用 lut.cube；异步文件面板防止重复点击嵌套。拒绝覆盖、原件字节不变，失败时不发布 Live 半成品。参数记录尚不是可自动恢复的项目历史；数据库、草稿、多选同步、目录 / 设备导入与路径合并仍待接入。

调色后的预览成本

补测当前浮点图片引擎：合成 4000 × 3000 SDR JPEG，1600px 预览，17 阶暖调 LUT、70% 强度与旋转，预热后 40 个角度。生成可读取像素的 RGBAh 位图，中位耗时 8.65 ms、P95 11.13 ms；首次加载加滤镜预热约 99.61 ms。这比实际 Metal 画布多了 CPU 可读位图落地步骤，但不包含 drawable / 屏幕显示，也未测 HDR 源文件解码，不能换算成 UI 帧率。原始数据与测量范围已保存。

性能与任务先测实际大图片、4K 视频与快速切换；再用约一万项混合库测索引 / 缩略图，测试导出取消、设备断开和失败后的重试。记录首屏时间、切换延迟、播放情况、内存与导出耗时；按目标 Mac 制定性能阈值。失败或取消任务不标记成功，不覆盖原件；缩略图和导出在后台进行。

GEOMETRY & STABILIZATION / 2026.10.03

画面校正进入首版，稳像先做独立验证。

画面不正与运动抖动分开处理。首版优先支持方向纠正、手动拉直和裁切；视频 / Live 稳像作为贴近核心的可选实验，不与后续 AI 剪辑和动画混在一起。

问题工作台操作边界与优先级
横竖 / 方向错误先正确读取照片方向与视频 preferredTransform；再提供 90° 旋转和翻转。图片、视频与 Live 都验证预览 / 输出方向。正确解读元数据与用户额外旋转要分开，避免二次旋转。
地平线倾斜角度滑块、网格辅助、固定比例 / 自由裁切；自动拉直建议以后独立评估。手动拉直进入首版。旋转后需要裁掉边缘空白，允许查看裁切范围并恢复。
建筑透视歪斜后续可增加垂直 / 水平透视调整。与简单旋转不同，先记录为几何扩展，不让它阻塞调色和 Live 闭环。
视频 / Live 抖动按所选片段分析运动轨迹，平滑短时抖动；提供稳像开关、强度与裁切范围预览。先验证轻微手抖和静态场景，保留有意平移 / 摇镜的能力需要测试。剧烈运动、视差、运动模糊或滚动快门可能导致估计失败 / 形变，不能承诺恢复为三脚架画面。

放入右侧“裁切与校正”

延续深色参数栏，按需展开旋转、拉直、裁切；稳像仅在视频 / Live 的运动部分可用，采用“分析所选片段 → 前后对比 → 保留 / 撤回”。稳像旁的 i 说明处理时间和边缘裁切，图片不显示无效的运动稳像控件。

Live 封面与动态部分一起对齐

视频转 Live 时，封面从最终几何校正 / 稳像后的选定时间帧提取，导出共同画幅的照片和视频。编辑已有 Live 时，尽量保留高质量静态资源，按封面时间的变换与同一裁切坐标处理；两资源分辨率 / 构图不同需验证对应关系，不能默认拿低清视频帧替代原照片。

一键自动校正的交互

支持自动化方向：用户对当前素材或所选片段点击“自动校正”，本地视觉算法检测可用的地平线 / 垂直结构并估计倾斜；视频 / Live 同时评估运动。算法提出角度、稳像与裁切方案，应用生成可撤回的效果预览，并展示裁切范围。也允许用户一键保留结果或继续手调，原件不变。

自动检测是待验证能力：缺乏可靠水平参考、透视明显或运动估计失败时，保留原状态并提示手动调整；不把有意斜构图、平移 / 摇镜一律修正。自动稳像仍需本地时序分析，不能仅凭几张图或 Sol 的文字建议确定所有帧的精确变换。首版手动几何校正不依赖自动检测；自动模块通过真实素材验证后再启用。

自动调正的识别路径

先按图片 EXIF 方向和视频 preferredTransform 规范坐标，防止把横竖屏标记当成倾斜。首个识别实验使用 Apple Vision 的 VNDetectHorizonRequest，取得地平线校正建议；Core Image 执行几何变换并生成裁切预览。使用观察结果提供的校正变换，核验角度单位、正负方向和坐标约定，不直接凭界面角度反号。

建筑 / 室内场景作为下一步：提取直线或矩形边缘，按方向聚类，用多条一致的水平 / 垂直参考估计旋转；矩形检测本身不能判断哪条边应当水平，也不能直接消除建筑透视。自动判断结合参考线一致性、检测分数、建议角度和裁切损失，阈值通过真实素材校准；系统检测分数不当作校正正确率。

视频只对用户选定片段的低分辨率分析帧估计角度，分镜头聚合；近似恒定倾斜先使用整段固定校正角度，避免逐帧独立旋转造成画面晃动。有意横滚、切镜或建议冲突时保留原状态。需要时变校正时另做时序平滑与固定安全画幅验证，不能将稀疏帧拉直等同于稳像。Live 的照片与动态部分需对齐同一画幅；视频转 Live 从最终变换后的封面时间帧提取静态资源。

目标交互为“自动调正 → 显示建议角度与裁切框 → 可手调 / 撤回”。首个图片原型已接入地平线识别、角度滑块、自动安全裁切后的预览、网格 / 原片对比和恢复；单独裁切框、建筑分析、跨会话识别缓存、批量自动和视频 / Live 时序处理仍待实现。先用真实海平线、建筑、无参照与斜构图素材验证准确率，再启用批量自动。

当前原型边界：分析使用摆正后的最长边 1024 像素副本。实验门槛为分数 ≥0.6、角度 ≤10°、裁切面积损失 ≤35%，小于 0.15° 不自动应用；门槛尚未校准。导出为新的 8-bit sRGB SDR PNG，不保留 HDR / 增益图或 EXIF / GPS，不覆盖已有文件。受限命令行环境内 Vision 模型可能出现 CVPixelBuffer / 系统查询错误，属于运行错误；本机应用环境已验证可调用。合成图返回无可靠参照，应用正确保留现状；尚未取得真实照片识别精度结论。

Apple 地平线检测与校正观察结果提供本地识别起点；并非已验证等同于“照片”应用的自动裁切算法。

后期稳像的实现路径

几何变换可使用 Core Image / 视频合成管线。稳像需要单独建立“运动估计 → 区分运镜与抖动 → 轨迹平滑 → 帧变换 → 安全裁切”模块。Vision 图像配准可以作为运动估计的一个候选组件，但它本身不是完整的后期稳像引擎。

Apple 视频变换接口提供几何变换能力，具体接口需按目标 SDK 选择；Vision 图像配准估计两图之间的变换。采集稳像接口作用于相机采集连接，不能直接作为已拍摄视频导入后的稳像开关。

处理仍以本地引擎执行，不需要逐帧调用 Sol。原件保留，旋转角度、裁切、稳像设置和变换曲线记录进配方 / 分析缓存；改 LUT 不必重新估计运动。用户恢复原片时切回无调整配方。

控制计算量与验证结果

只分析选中的 Live / 视频区间及必要的前后上下文；低分辨率副本估计运动，变换映射回原分辨率渲染。分析缓存关联源资源版本、源时间戳、区间、算法与几何坐标版本；改变区间 / 算法时检查失效，调色单独改变可复用。按镜头边界重置，不能把切镜当成抖动。

验证横竖屏、轻微手抖、有意运镜、近景视差、低光模糊与切镜；检查黑边、边缘裁切、画面呼吸 / 形变、封面跳变、音画同步、HDR 高光和预览 / 导出一致。记录处理时间与 GPU / 内存负载。估计失败时保留未稳像版本并说明限制，不把失败任务记作已修复；数字稳像不能自动恢复拍摄时已经模糊的细节。
