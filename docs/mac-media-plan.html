01 / PRODUCT DIRECTION

做轻量素材工作台，先打通核心闭环。

产品核心是“找到 → 看清 → 收藏/比较 → 轻编辑 → 导出”。原件可以保留在外接设备上；需要编辑或离线使用时，再创建本地工作副本。

读取与浏览

连上设备就能找素材

统一图片、视频与 Live Photo 列表；设备状态、缩略图和来源位置清楚可见。手机完整预览通常需要按需下载到缓存。

调色与截取

常用操作保持轻量

曝光、白平衡、对比度、饱和度、LUT 强度；视频选起止点与封面帧，输出匹配的照片与短视频资源。

索引与收藏

一份素材，多处存在

收藏与编辑记录绑定素材身份。相同文件可以在卡、SSD 和手机导入缓存中各有一个位置，列表只展示一份。

适合：希望持续迭代，保留后续产品化选择

建立自己的 UI 和索引模型，按模块引入 MIT 组件。借鉴 FlowVision 的功能取舍，评估 SimpView 的 PTP 与浏览实现；首版调色优先用 Core Image，需要复杂渲染时再引入 MetalPetal。

代价：要自己实现浏览、缓存和导入协调。收益：Live Photo、多位置索引和非破坏编辑可以从一开始统一设计。

适合：接受 GPL 路线，优先快速做自用或开源验证

FlowVision 的 README 已声明图片、视频和 HDR 浏览，最接近当前需求。先编译、跑真实素材，再评估收藏、来源关联、LUT 与 Live Photo 的新增工作量。

GPL-3.0 影响派生软件的分发方式，收费本身不等于禁止；闭源分发路线需核查许可要求。现有构建涉及旧 ffmpeg-kit，迁移和依赖构建也要计入工作量。仓库依据

02 / OPEN SOURCE SHORTLIST

有可复用的积木，没有核实到完整成品。

下面区分完整应用、组件库和格式参考。核查依据为公开 README、许可证信息与部分源码；尚未编译候选或实测设备。

项目能复用什么边界与许可建议
FlowVision

最接近完整浏览器

图片/视频混合浏览、HDR、目录浏览与布局。GPL-3.0；README 构建步骤涉及旧 ffmpeg-kit 的 GPL 构建；不能据此认定已满足调色、Live 导出和多源合并。优先体验与实测；接受 GPL 路线时再考虑 fork。
SimpView

轻量原生参考

Swift 看图、键盘/手势浏览、USB PTP 相机访问。MIT；macOS 15+ / Apple Silicon。无完整缩略图库、编辑或动画支持；PTP 相机可用不代表 iPhone 全部素材可用。适合核查并适配少量浏览与设备模块。
MetalPetal

可选渲染组件

Metal 图片/视频处理、滤镜图、色彩查找。核心 MIT；Examples 有独立许可证。引入库不自动保证 HDR 保真，需配置并测试管线。Core Image 不够时再引入，避免初期双套滤镜系统。
GRDB.swift

推荐索引组件

Swift SQLite 数据访问、素材关系与编辑记录存储。MIT；哈希、Live 配对、多源身份仍由应用实现。作为目录数据库；更小的 PoC 也可先用 SQLite。
LimitPoint / LivePhoto

格式研究参考

解释照片/视频标识配对与封面时间元数据。未发现明确开源 LICENSE，源码写有 All rights reserved；UIKit 实现，使用 8-bit BGRA 与 H.264，不能视为 Mac HDR 导出库。研究格式，不列为直接复用依赖；原生模块需独立实现或另找授权明确的组件。
MLX Swift LM

后续 AI 候选

本地 LLM / VLM 推理集成；可用于标签和画面理解。MIT 框架；模型权重许可、内存占用与画面理解质量单独评估。不要把示例仓库当当前核心库入口。作为可选能力，媒体闭环完成后加入。
依赖更新：旧 FFmpegKit 已退役；其官方 README 指向源码分发的 FFmpegKitNext。如以后需要补充非系统视频格式，可以评估新路径或自行构建 FFmpeg；MVP 优先 AVFoundation。具体 FFmpeg 构建许可按 官方说明核查。

UI 参考按 chitaner 的 Picview 理解，它的官网明确强调极简、手势和多窗口。picview.org 是另一个同名项目，不能直接当成你所指 APP 的源代码；收藏作为本项目需求保留。

04 / COLOR & LIVE PHOTO

HDR 是全链路能力；Live Photo 是一组关联资源。

HDR 显示

先保住正确的亮度和色彩

普通视频先走 AVPlayer / AVPlayerLayer；需要调色时，按 Apple 的 EDR 路径获取视频帧，经 Core Image / Metal 处理后显示。图片要使用支持 HDR 的解码和显示路径，避免早期转成 8-bit SDR。

Apple HDR 视频流程 · HDR 图片样例

显示与导出分开验收

屏幕看对，不代表文件写对

检查亮度扩展、色域、传递函数、位深和元数据。SDR 屏幕提供正常的 tone mapping；移动到另一块显示器时更新策略。缩略图可使用 SDR 衍生缓存，不能据其判断原片 HDR 是否保留。

调色后重新编码不能假定 Dolby Vision 动态元数据原样保留；“HDR 导出”必须按格式和设备组合验证。

LUT 要区分“还原”与“风格”

DJI 官方提供 Pocket 3 的 D-Log M → Rec.709 .cube，这条输出路线是 SDR。只有匹配输入模式时才能正确使用；HLG、普通 Rec.709 与 iPhone HDR 需要各自的色彩处理。

DJI 官方 LUT · Core Image 3D LUT

LUT 模块的具体边界

自行解析 .cube 的网格与 DOMAIN 信息，转换为 3D LUT 数据；对接 Core Image 或 Metal。为每个 LUT 保存输入/输出色彩说明、来源、摘要和版本；无法可靠识别拍摄模式时让用户手动选择。LUT 强度混合应在合适的色彩空间进行；仅开启外插选项不等于完成 HDR 适配。首版支持用户导入 LUT，官方免费下载不能据此推定可以随 APP 再分发。

视频 → Live Photo：截取、选封面、配对、验证

01选择片段

默认约 3 秒，可调整；这是交互默认值，实际可用长度与格式需实测。

02选择封面帧

封面来自截取范围内的实际帧；旋转、裁切与调色和视频一致。

03写成资源对

照片 + MOV；共享内容标识，视频包含对应的封面时刻元数据。

04苹果端识别

资源加载、Mac 照片导入、转回 iPhone 后的实况播放逐项验证。

首个兼容目标建议是 SDR JPEG + H.264 MOV，成功后再验证 HEIC / HEVC 与 HDR 组合。这个顺序服务于兼容性验证，不表示任意 JPEG + MOV 都会被识别为 Live Photo。Live 编辑后必须同时更新静态图与运动片段。

播放可评估 PHLivePhoto + PHLivePhotoView。本机 SDK 已确认 macOS 的资源加载和 NSView 接口存在；Apple 页面中的旧概述存在仅编辑扩展可用的表述，需以目标 SDK 和实际运行验证为准。资源加载文档。配对元数据概念见 格式参考，其旧实现不作为 HDR 方案。

“全功能预览”需要先变成可测试的格式清单

优先 JPEG、PNG、HEIC（含 HDR 测试样本）、常见 TIFF；视频优先 MOV/MP4 内的 H.264、HEVC，验证 iPhone HDR、Pocket 普通/HLG/D-Log M。GIF/动画 WebP、具体相机 RAW 型号、ProRes 和其他封装分批测试；扩展名并不保证可解码。安卓 Motion Photo 不自动等同于 Apple Live Photo，后续需独立解析与转换。

05 / ASSET IDENTITY

合并的是素材身份，原件仍有各自的位置。

“手机里一段视频，卡上也有一段”包含两种情况：原字节相同，或来自同一次拍摄但已转码/裁剪。两者需要不同的关系，才能保住原片、画质与编辑记录。

确认为完全相同

多个 Location 指向一个 Resource

文件大小与局部哈希先筛选，再用完整内容 SHA-256 确认。内容一致后，在同一素材下增加位置；名字和路径不同也能关联。连接协议提供的设备 ID 只用于定位，不能替代内容确认。

相似 / 转码 / 裁剪副本

保留为独立版本，建立 RelatedGroup

结合时长、拍摄时间、分辨率与采样画面提出候选。用户确认关联，保留源设备、码率、HDR、完整/裁剪状态；相似度和“更大文件”都不能自动证明哪份是更好的原件。

断开设备、重连、缓存与导入
  • 可挂载来源：直接引用原件，记录卷身份与相对定位；安全书签负责权限。重连时重新验证资源，不把相同路径当作相同内容。
  • PTP 手机来源：先列目录和缩略图，完整预览/编辑时下载指定资源；若存在匹配的本地副本，优先复用。下载到临时文件，完成验证后原子移动。
  • 离线时保留缩略图、收藏和配方；已存在的工作副本可继续使用。只有远端原件的任务进入等待来源状态。
  • 完整哈希会产生大量 I/O，尤其是存储卡与手机；采用后台队列、进度与取消。手机资源未下载时只展示重复候选，不声称完成精确合并。
  • 导入中拔线：失败/待重试可恢复，不把半文件登记为可用原件。首版逻辑合并不自动删除副本；物理清理作为独立后续功能。

06 / EXPERIENCE CONCEPT

浏览保持简洁，编辑采用 Lightroom 式工作区。

浏览状态沿用 Picview 的沉浸感；进入编辑状态后，画布居中、右侧参数、底部素材条，历史与版本比较按需展开。学习讲解围绕当前工具出现。初期不需要复制 Lightroom 的全部模块，保留混合媒体和设备来源的核心能力。

浏览状态

找素材、预览、收藏、多选；侧栏和工具栏可隐藏。优先让画面清楚，适合快速筛选手机与存储卡素材。

编辑状态

中性深色画布，支持明暗界面；右栏按“光线 → 色彩 → 风格 → 裁切 → 导出”组织，直方图按需显示。右栏的“讲解”入口解释当前参数，不占据主画布。

浏览时的交互

左右键切换；滚轮/触控板缩放；空格播放或暂停；F 收藏（建议映射，可改）；Esc 回到网格。缩放位置可随同组图片保持，工具栏按需出现。

比较时的交互

图片先做 2-up / 4-up、同步缩放与同位置检查；调色做原片/结果 A/B。视频先支持同一片段的编辑前后比较，再扩展到两段独立视频。

跨设备视频如有转码、裁剪或不同起点，同步播放必须维护时间偏移；不能仅因时长相同就假定画面逐帧对齐。

07 / LEARN WHILE EDITING

用自己的素材，理解每一次调整。

把术语、拍摄参数和编辑反馈连成一条可操作的学习路径。用户随时可以只编辑；开启“边修边学”后，用短解释和可跳过的练习帮助理解自己的决定。

Adobe 的桌面端学习文档已有逐步教程与 Interactive Edits，可供借鉴。下面的“围绕自己素材学习”与个性化复盘是本项目设计建议。官方学习机制

01 · 目标想让画面怎样？

还原自然、突出主体、暖色氛围或黑白。先记录用户意图，再讨论参数；不存在所有照片通用的唯一正确数值。

02 · 理解解释当前工具

点击参数名称，查看一句定义、影响范围、何时使用，以及它与相邻工具的区别。

03 · 试调每次只验证一个改变

拖动参数即时预览，比较调整前后和相关区域；练习可以跳过，完成后保留用户自己的数值。

04 · 复盘回看怎样得到结果

在编辑历史里逐步回放，解释参数变化；保存风格配方和个人笔记，下次同场景可复用。

围绕具体操作，安排三层学习内容

术语随工具出现

正在调什么，就解释什么

曝光、高光、阴影、白色色阶、色温、色偏、曲线、自然饱和度、LUT。术语卡保持简短，需要时再展开更完整的内容。

拍摄信息随素材出现

理解拍摄条件

有元数据时展示 ISO、快门、光圈、焦距与设备；说明它们可能如何影响噪声、运动模糊和景深，并给出下一次拍摄可尝试的选择。

过程随编辑出现

知道为什么这么改

保存参数前后值、版本、用户目标和可选笔记。用户主动点“解释这一步”时，结合实际变更和画面解释，避免空泛评价。

拍摄时的光圈、快门和 ISO 是记录，不能靠后期滑块改回拍摄条件。后期“曝光调整”改变渲染亮度，不等于重新拍摄。JPEG/视频的色温调整与 RAW 的白平衡处理也有不同边界；缺失元数据就显示未知，不能让 AI 推测值伪装成实测参数。

一段真实编辑流程应该怎样结合学习

用户操作贴近当前素材的讲解下一步验证
打开一张逆光照片先问用户想保留剪影，还是让主体更清楚；检查素材类型、已有配方和可用画面信息。选择编辑目标，再建立调整前快照。
点击“高光”解释高光主要影响明亮区域，和整体曝光调整的作用范围不同；若目标是控制天空，先单独观察这一项。试调后看天空层次、主体亮度及边缘是否出现不自然变化。
调整“阴影”解释它如何影响暗部；提示用户观察噪声和灰雾感。亮起来不自动等于质量更好。放大暗部与原片比较，决定是否保留。
调整白平衡如果希望还原自然，观察可用中性参考与肤色；如果希望暖色氛围，记录这个风格目标。对比暖色变化与主体表现；没有可靠中性参考时不给出“色温准确”的断言。
套用 LUT说明这是输入还原还是创意风格；展示已适配的输入模式，并检查叠加后的高光、肤色与饱和度。做原片/结果 A/B，保留用户选定的强度。
保存结果复盘“调整了哪些参数、观察到什么、为何保留”；可以加入用户笔记。保存配方，再决定是否同步到同组素材。

上述为假想流程，尚未分析真实照片。不能承诺调低高光就能恢复已丢失细节；画面区域与结果判断必须基于实际渲染和可用源数据。

默认同步风格，曝光允许分别保留

同步窗口可勾选 LUT、强度、色彩与光线参数；区分“复制相同数值”与“在现有调整上增加变化”。默认不覆盖未选参数，多份素材值不同则显示“混合”。

输入色彩模式不同的素材先匹配转换，再应用共同风格；不兼容项说明原因并保留原状态，离线原件的渲染进入等待队列。

讲清这次批量操作改变了什么

提交前展示同步范围和代表性对比；应用后形成一个批次记录。Live 的封面与运动部分一起处理，视频可指定整段或片段。

支持撤回该批次；如果素材之后又有独立编辑，提供版本选择，避免撤回批量操作时覆盖后来的修改。

视频和 Live 的学习要覆盖时间变化

视频除了当前帧，还要采样片段起点、中间、终点及显著场景变化，检查同一配方是否导致时序亮度/色彩不一致。Live 要同时看高质量静态封面与运动片段；可补充“封面选择、动作完整性、裁切与稳定”小练习。

AI 怎样参与，才能帮助形成自己的判断
  • 第一版先做经校对的静态术语卡、工具解释、编辑历史和 A/B；即时滑块响应由本地引擎完成，不等待 AI。
  • AI 根据当前素材、用户目标、实际参数差异和分析信号返回解释与可试方案。每条解释区分确定的参数变化、算法测量和主观风格建议。
  • 用户完成拖动或主动点“解释”时才分析；按配方版本绑定请求，过期响应不覆盖新操作。建议以可撤回的预览呈现，由用户选择是否保留。
  • 直方图、剪裁比例和对比信号注明分析阶段与色彩空间；HDR 超过 SDR 白点的数值不自动视为过曝，也不把 tone-mapped 预览统计当源 RAW 信息。
  • 不为所有作品给一个“专业评分”，不把暗调、暖色、剪影等创作选择自动判错。技术缺陷与风格取舍分别说明。
  • 后续可按使用记录安排可选练习：高光/曝光区别、白平衡、曲线、Log 还原与 HDR 输出。内容需原创或取得许可，不抓取 Adobe 教程作为应用内课程。
原生实现需要增加的记录与验收

为编辑操作保留 command/snapshot 历史；Undo/Redo、版本比较与批次事务以真实配方为依据。知识卡绑定 parameterID 和媒体适用范围；拍摄元数据记录来源；用户主动接受或撤销 AI 方案时，记录建议版本与实际参数差异。

验收：术语和真实滑块匹配；关闭学习后编辑流程照常；讲解引用的数值与当前版本一致；元数据缺失显示未知；混合批量不会覆盖未选参数；能恢复单份和整个批次。教学有效性再通过少量用户试用观察，不能仅凭点击次数宣称学会摄影。

08 / BUILD & VALIDATE

以真实素材验收，逐个解除技术不确定性。

先做小规模原生验证，拿到结果后再安排工期。AI 能帮助写实现和排查问题；设备协议、HDR 观感与 iPhone 实况识别仍需要真实环境测试。

阶段具体交付通过标准
P0 · 技术验证HDR 原片/调色画布；SDR Live Photo 生成；iPhone 枚举与按需下载。HDR 在同机“照片”/QuickTime 中对照正常；Live 资源能被 Mac 照片与 iPhone 识别播放；手机视频和 Live 资源对可可靠获取。若 USB 路径有阻碍，首版保留 Image Capture 导入文件夹入口。
M1 · 原生浏览文件夹/存储卡；混合缩略图；图片缩放、视频播放、已有 Live Photo；收藏、2-up 比较和本地索引。已声明格式集可浏览；拔卡后收藏还在；一万项混合文件样本下主界面保持响应，按需加载；通过已约定机器上的性能基线。
M2 · 编辑闭环曝光/白平衡/对比度/饱和度；用户 .cube LUT；A/B；混合多选与选择性同步；按需 i 术语说明、历史与快照；旋转 / 手动拉直 / 裁切；片段和封面选择；原声静音 / 音量；SDR Live 导出。原件字节不变；重启后配方恢复；预览与导出在同一显示条件下无明显色偏；静态封面、声音和视频一致；取消/失败不留下“成功”条目。
M3 · 多源关联USB 手机入口；精确重复多位置；重连/离线；相似/转码候选；缓存与工作副本。改名的相同文件只显示一个素材；完整 Live 不与单张静态图误合并；转码文件保留独立版本；中途断开可重试。
M4 · 扩展HDR Live 导出验证；更多 RAW / 视频格式；安卓；后续 AI 标签、选片、调色解释、摄影学习，以及短片 / 口播 / 字幕 / 动画的独立扩展评估。按格式与设备逐项发布兼容清单；AI 提议可撤回，讲解与当前配方版本一致；确定性编辑和导出仍可离线完成。

编辑建议

看画面，给出配方

“更自然、压一点亮部、保留肤色”转换为受约束参数或已知 LUT 的建议，预览后可接受/撤回。视频建议按镜头或片段保持一致，避免逐帧建议导致闪烁。

素材理解

找场景与精彩片段

标签、自然语言检索、清晰/稳定封面帧和片段推荐。先传递采样帧与必要元数据；本地模型和云端服务各自验证成本、许可与效果。

“生成式修图/改视频”作为另一个后续功能评估：它可能改动内容，且需要时序一致性与色彩保真验证。首版的调色、裁切和导出由 Core Image / Metal / AVFoundation 执行，AI 服务可以完全关闭。
建议准备的最小验收素材集
  • iPhone：普通 HEIC、带 HDR 信息的 HEIC、已有 Live Photo 的完整资源对、HDR MOV；包含横竖屏、声音与慢动作样本。
  • Pocket：实际机型的普通、HLG、D-Log M 视频各一段；对应官方还原 LUT。若机型不支持某模式，调整测试集。
  • 重复组：原件改名拷贝、相同原件多路径、手机转码版、裁剪版、Live 配对视频缺失、同名但不同内容。
  • 异常组：只读卡、拔线、照片库权限被拒绝、文件修改、存储空间不足；不必以处理所有损坏格式作为第一版发布条件。
  • 显示与性能：实际 EDR 内屏 + 常用外接屏；4K HEVC、较大图片、一万项混合目录；测首屏、导航延迟、内存与后台 I/O，再确定目标。
