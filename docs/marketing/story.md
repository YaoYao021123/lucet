# Lucet 光集的故事：和 AI 一起把它做出来

Lucet 光集不只是一个调色工具，**它本身就是一个故事**：一个原型，一句句人话，一次次改，最后变成真正能用的 App。这个故事最容易引来的，是同样在用 Claude Code 之类的工具做东西、想找人交流的人。下面是素材，发帖时挑你觉得最有意思的 2–3 个讲。

> 这些都是项目里真实发生过的事（依据 `git log` 和我们的对话）。发之前你再核对一遍，改成你自己的口吻；**别写没发生的**。最近一次整理：2026-10-20（到提交 `b73f531` 为止）。

## 1. 故事的骨架

1. **起点**：第一版是 ChatGPT 写的原型。仓库的第一条提交就叫 “Baseline: ChatGPT prototype as received”。
2. **挑毛病**：把它交给 Claude Code，第一件事不是加功能，而是找问题：速度、界面，还有别的。
3. **一句人话驱动设计**：每次改动几乎都来自一句普通的话（见下面第 3 点）。
4. **AI 会错，人来把关**：好几个 bug 都是你一眼看出「这不对」才修好的（见第 4 点）。
5. **同样的方式做了全套**：App、官网、宣传视频、图文卡片、这套白板图，都是同一种做法。
6. **越做越多**：一位合作伙伴做了网页版（开源），里面的相似连拍分组、匹配色调、LUT 导出、局部调整，加上你挑的九项功能，都在 Mac 上用原生代码重做；又加了中英文界面、项目、AI 调色和 AI HDR（见第 2b 点）。
7. **邀请**：想一起做的人，欢迎来。

## 2. 「挑毛病」找到了什么（有实测数字）

这些是第一轮改造时在你的 Mac 上量出来的，数字来自项目的测试记录：

- 把一个有 **2000 个文件**的文件夹加入素材库：原型约 **6.9 秒**（界面卡住），现在不到 **0.01 秒**。
- 打开 DJI 官方的 **Pocket 3 Spring / Winter Pro LUT**：原型直接导入失败（文件标题是 GBK 编码），现在能正常导入；解析一个 64 阶 LUT 从约 600 毫秒到约 20 毫秒。
- 拖动一个滑块：原型会让整个界面重绘；现在只重绘那个滑块和画面。
- 导出照片：原型只能存 PNG 且丢失全部拍摄信息；现在可以选 JPEG / HEIC / PNG，保留拍摄时间和相机信息。

（完整对比表在 `docs/DEVELOPMENT.md`。）

## 3. 「一句人话」改变了什么

这些是你的原话大意，和它引出的改动。很适合做成「我说了什么 → 它改了什么」的图文：

| 我说的 | 之后改成了什么 |
|---|---|
| 「液态玻璃的界面不见了，我想保留」 | 把 macOS 26 的玻璃效果找回来，并用在选项卡和滑动条上 |
| 「右边不够紧凑，行距太松」 | 检查器整体收紧 |
| 「教学太固定，不会随用户变」 | 做了会读这张照片、随水平和兴趣变的「边调边学」，还有可选的「问问这张照片」 |
| 「金色不适合做强调色」→「这个蓝太亮了，有些强调色没必要」 | 界面改成克制的中性灰，强调色只留给主要按钮 |
| 「可以像『影调』这样把概念分开」 | 基础调色按曝光 / 影调 / 白平衡 / 色彩分组 |
| 「信息不够」 | 重做了「信息」页：拍摄参数、编码、色彩、位置、编辑记录 |
| 「对新手不够友好，找 bug」 | 找到并修了一批：照片被误判过曝、文件移动后找不到、导出时退出会丢文件，还加了「自动」和简单模式 |
| 「方框太多了」→「一个方框都不要」 | 网页改成完全扁平 |
| 「工具栏里的切换，框里又套了个框」 | App 里的分段控件改成只剩一块滑动的玻璃高光，没有外框；检查器的标签页和简单 / 完整开关也一样 |
| 「面向全球，英文要有」 | 整个界面、README 和网站都有英文 |
| 「同一件事的照片，应该一套颜色，改一张全跟着变；一张照片可以在好几个项目里」 | 做成了「项目」：共用一套颜色，每张照片的曝光、裁剪各管各的，一张照片可在多个项目里各有版本 |
| 「GitHub 首页那张图，右边的字是黑的，在深色背景上看不清」 | 查下来：窗口截图里，半透明检查器上的次要文字被画成了近黑色；改成直接取面板单独渲染时（文字是对的）的那一列，截图脚本还会固定并检查窗口尺寸（`a31eba2`） |

## 4. 「AI 也会犯错」的真实瞬间（最讨喜，也最可信）

- **白底拿铁照片被说「整体偏亮」**，教练建议曝光 −1.5。你一试就知道不对：白桌子本来就该亮。查下来是规则只看了中间亮度，没看有没有真正的暗部。已修，并加了测试。
- **网页里的面板截图被切掉一截**。原因是我（AI）用的截图裁剪命令，偏移写成 `0 0` 时会被当成「从正中间裁」。你说「有些截图不清晰、截断得多」，才发现了。已修，脚本里也写了这个坑。
- **前后对比滑块一度是假的**：同一个裁剪 bug 让「调整前」那张图其实混进了「调整后」的一半。修好后页面上写的「真实结果」才名副其实。
- **README 里前后对比 GIF 的白色分隔线从来没动过**：做 GIF 的命令里，`drawbox` 的 `t` 是线的粗细，不是时间。线现在是在混合表达式里画的，会跟着扫动；四张 GIF 都重新生成了。（提交 `f3c8fe2`）
- **编辑 Live Photo 后导出，只剩一段视频**：Live Photo 在编辑器里是以它配对的视频打开的，所以导出「当前这张」悄悄存成了普通视频，照片那一半丢了；只有批量导出知道 Live Photo。现在导出面板会让你选：Live Photo（默认）/ 仅照片 / 视频，并在存之前用系统接口检查配对。（`351e666`）
- **从无人机视频做出的 Live Photo，在「照片」里被归到「今天」**：封面是视频里截的一帧，没有拍摄日期和地点，影片也没有创建日期。现在会读出视频的日期、地点和机型，写进两半。（`c5ee841`、`8dc5fc9`）
- **iPhone 的 HDR Live Photo 导出后变成了 SDR**：重用原照片时把增益图丢了。现在保留。（`8227224`）
- **有些编码器（比如 ffmpeg）生成的视频，开头有几毫秒的「空」**，拉直这一步碰到一个无限大的尺寸，直接把 App 弄崩溃了。修好后加了测试。（`d8b294c`）
- **深色面板上的文字和图标对比度不够**：播放按钮的白色符号落在浅色玻璃上只有 1.5:1；次要文字用的是系统默认色，在深色面板上太淡。做了一次外观审计，列出 F01–F06 六项，统一了可读的次要文字色并修好。（`6fc3215`，报告在 `docs/audits/2026-10-18-appearance/`）

这类故事的价值是：**它说明 AI 做东西靠的是「你看、你说、它改、再验证」的循环，而不是一键魔法**。

## 6. 说话要注意

- **准确描述分工**：原型是 ChatGPT 写的；改造、网页、视频是在 Claude Code 里完成的；方向、品味和拍板是你。别说「AI 全自动做完」，也别说「我一个人写的」。有些部分（比如 3D 互动课）是 Claude Code 派出的子智能体做的，你和它审过；要讲细节时可以这样说，但别夸大。
- **别踩别人**：不要说 ChatGPT「不行」。事实是「它给了一个能跑的起点，后来的问题都是实测出来的」。
- **合作伙伴**：只用 README 里的措辞（「一位合作伙伴做了网页版，开源，Apache-2.0」），不点名、不放对方的链接，除非对方同意；也不要替对方说他们的经历或身份。
- **两个模型是别人的研究**：AI 调色是 Zeng 等人的 Image-Adaptive-3DLUT（Apache-2.0），AI HDR 是 Liao 等人的 GMNet（MIT）。说清楚是我们把它们接进 App、在本机跑，不是我们训练的。
- 数字要带上下文：「导入 2000 个文件从 6.9 秒到 0.01 秒以内」指的是加入素材库这一步，缩略图仍需要时间生成。AI HDR「约 1.3 秒一张」是空闲的 Mac 上的数字，之后会缓存。
- 想邀请别人一起做，**请先给仓库选一个许可证**（现在仍然没有 `LICENSE`），否则别人没法放心地改和分享。
- 不提价格；不暗示和 DJI、Apple、Anthropic、OpenAI 有合作。
